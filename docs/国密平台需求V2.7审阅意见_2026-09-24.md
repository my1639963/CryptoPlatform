## 一、H 级（必须修改）

### H-01 StringToSign 公式与冻结测试向量不一致

3.3.3.2 的公式为：

```text
stringToSign = HTTP-Method + "\n" + CanonicalURI + "\n" + CanonicalQueryString + "\n"
             + CanonicalHeaders + "\n" + SignedHeaders + "\n" + HexEncode(SM3(RequestBody))
```

其中 CanonicalHeaders 的格式定义为"每项 `key:value\n`"。按此**存在两种合法读法**：CanonicalHeaders 整体末尾带不带 `\n`。带 `\n` 时，公式中的 `+ "\n"` 会在 Header 块与 SignedHeaders 之间产生一个空行。

本次用独立实现（OpenSSL SM3 + HMAC-SM3）对 V2.7 冻结的固定向量实测：

| StringToSign 读法 | 计算结果 | 与文档固定签名比对 |
| --- | --- | --- |
| Header 块末尾**带**换行（严格按公式字面） | `ot4p3NiRpYDFymaGgS0Fo0Zle541ziYoaOAPB0qs7ls=` | ✗ 不匹配 |
| Header 块末尾**不带**换行（按文档示例风格） | `KfuluxDM90Ze4jQtQeSG5AZ/MubbtzoA3vFoKslQFfc=` | ✓ 匹配 |

向量本身数值正确（SM3("")、SM3(Body) 均已验证），问题只在**公式文字有歧义**。而 V2.7 明确规定"该测试向量作为 V2.7 编码基线固定值；实现不得自行替换 Canonical 规则"——跨语言实现若按公式字面实现，固定向量校验必然失败。

**修改建议**：在 3.3.3.2 与 6.2.2 两处公式旁明确"CanonicalHeaders 为各 `key:value\n` 顺序拼接后**去除末尾换行符**的结果"（或等价表述），并用一句话声明：以 3.3.3.3 固定向量为唯一仲裁依据。

## 二、M 级（建议本期修改）

### M-01 GCM 计数器溢出的处置对象过宽，且与 Root Key 轮换的审批流程矛盾

3.1.3 规定 Counter 溢出时"触发 **Root/KEK/Data Key** 轮换流程并生成新的 KeyVersion"。两点问题：

1. (KeyId, KeyVersion, NodeId) 计数器耗尽只影响该 Data Key，触发 Root Key 轮换不成比例；
2. Root Key 轮换按 F-RK-004 是"安全管理员审批 + 二次确认"的人工流程，不应由运行事件**自动触发**，两处需求相互矛盾。

建议改为："停止该 KeyVersion 新加密 → 触发**该 Data Key 的 KeyVersion 轮换**（可自动执行）→ 审计告警"；如需 Root Key 轮换，仅产生"建议轮换"告警，由人工审批流程决定。同时建议明确：历史密文（旧 KeyVersion）的**解密不受影响**，仅禁止新加密。

### M-02 GCM 调用上限缺平台级约束，不满足 SP 800-38D

Nonce = KeyVersion(4B) + NodeId(4B) + MonotonicCounter(4B)，溢出判定按 (KeyId, KeyVersion, NodeId) 三元组，即**每节点**上限 2³²。而 SP 800-38D 对 96 位 IV 的 GCM 限定**每个 Key 的加密调用总次数 ≤ 2³²**。N 个节点合计可达 N×2³²，超出标准边界。

建议增加平台级要求："每个 KeyVersion 的 GCM 加密调用总次数（全节点合计）不得超过 2³²，建议按 2³¹ 设置告警阈值、2³⁰ 预留轮换缓冲"，并说明计数由集中服务或数据库统一聚合（NodeId 只保证 Nonce 唯一性，不承担总量控制）。

### M-03 Provider 能力模型缺"最小能力准入集"

V2.7 把 Wrap/Unwrap、Backup/Restore、Import/Export、RootKey 轮换全部改为可选能力，但未定义**Provider 可被平台使用的最低门槛**。平台自身密钥体系（L2 KEK-Runtime Wrap L3 Data Key；Software 模式的 WrappedMaterial 存储）硬依赖 CanWrapKey / CanUnwrapKey——一个不声明这两项能力的 Provider 在模型上是合法的，但平台根本无法完成启动。

建议明确：① SoftwareCryptoProvider 必须实现全部扩展接口；② HSM Provider 至少必须支持 Wrap/Unwrap（在 HSM 内部完成），否则不得准入；③ Backup/Restore/Import/Export/Rotate/Rewrap 为真正可选项，缺失时对应管理功能降级为不可用并明示。

### M-04 第 10 章测试需求未覆盖 V2.7 新增机制

V2.7 新增的三项机制在测试章节中没有对应用例：

| 新增机制 | 应补充位置 |
| --- | --- |
| GCM Counter 溢出 → 停止新加密 → KeyVersion 轮换 → 审计告警 | 10.4 密钥生命周期测试 |
| Provider 不支持可选能力时返回 NotSupported 并记录审计 | 10.2 或 10.5 |
| 恢复后 ProviderKeyIdentity / KCV / Fingerprint 身份校验 | 10.8（现仅列"Vendor Backup 恢复流程验证"） |
