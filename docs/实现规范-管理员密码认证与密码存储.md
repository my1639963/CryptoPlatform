# CryptoPlatform 管理员密码认证与密码存储规范

> 版本：1.0 | 适用范围：CryptoPlatform 管理员身份认证模块  
> 合规目标：等保 2.0 三级 + GB/T 39786-2021 商用密码应用安全性评估

---

## 1. 设计原则

### 1.1 管理员认证与密码服务分离

CryptoPlatform 作为密码服务平台，明确区分两条线：

| 线路 | 职责 | 关键组件 |
|------|------|----------|
| 管理员身份认证 | 用户名/密码登录、Token 签发、登录策略 | AdminTokenService, IPasswordHasher |
| 密码服务 | SM2/SM3/SM4 运算、密钥管理、HSM 抽象 | ICryptoProvider, IKeyService |

**重要澄清**：SM3 是密码杂凑算法，不等于密码存储 KDF。管理员密码存储必须使用专门的 KDF（Key Derivation Function），而非直接使用 SM3。

### 1.2 可配置 KDF 架构

密码哈希算法不写死，通过 `IPasswordHasher` 接口抽象，支持运行时切换：

```
IPasswordHasher
    ├── Pbkdf2PasswordHasher（默认，PBKDF2-SHA256）
    └── Sm3PasswordHasher（合规备选，PBKDF2-SM3）
```

## 2. KDF 选型

### 2.1 默认算法：PBKDF2-SHA256

| 参数 | 值 | 依据 |
|------|-----|------|
| 算法 | PBKDF2-HMAC-SHA256 | NIST SP 800-132, OWASP 2023 |
| Salt 长度 | 16 字节（128 位） | NIST SP 800-132 §5.1 |
| 迭代次数 | 600,000 | OWASP 2023 推荐最低值 |
| 子密钥长度 | 32 字节（256 位） | 与 SHA256 输出一致 |

**.NET 实现**：`System.Security.Cryptography.Rfc2898DeriveBytes` + `HashAlgorithmName.SHA256`

### 2.2 合规备选：PBKDF2-SM3

| 参数 | 值 | 依据 |
|------|-----|------|
| 算法 | PBKDF2-HMAC-SM3 | BouncyCastle PKCS5S2ParametersGenerator + SM3Digest |
| 迭代次数 | 100,000 | 商密场景建议值 |

**启用条件**：仅在密评机构明确要求使用国密算法进行密码存储时启用。  
**注意**：SM3 本身是快速杂凑，必须通过 PBKDF2 结构（迭代拉伸）才能作为密码存储 KDF 使用。

### 2.3 选型说明

| 考量维度 | PBKDF2-SHA256 | PBKDF2-SM3 |
|----------|---------------|------------|
| 标准依据 | NIST SP 800-132, OWASP | GM/T 0004 + PBKDF2 结构 |
| .NET 原生支持 | 是（Rfc2898DeriveBytes） | 否（需 BouncyCastle） |
| 密评接受度 | 高（国际通用标准） | 需配合完整商密方案 |
| 离线暴力破解抗性 | 600,000 次迭代 | 100,000 次迭代 |

## 3. 密码哈希存储格式

### 3.1 格式定义

```
{algorithm}${version}${base64salt}${iterations}${base64hash}
```

示例：
```
PBKDF2-SHA256$1$YWJjZGVmZ2hpamtsbW5vcA$600000$REPLACE_WITH_ACTUAL_BASE64_HASH
```

| 字段 | 说明 |
|------|------|
| algorithm | 算法标识，如 `PBKDF2-SHA256`、`PBKDF2-SM3` |
| version | 算法版本号，整数，从 1 开始 |
| base64salt | Base64 编码的随机 Salt（16 字节） |
| iterations | 迭代次数，十进制整数 |
| base64hash | Base64 编码的子密钥（32 字节） |

### 3.2 设计要点

- **自描述**：哈希字符串本身包含算法、版本、参数，无需额外字段解析
- **可验证**：验证时使用存储字符串中的 Salt 和迭代次数重新计算
- **可升级**：通过比较 algorithm/version/iterations 与当前默认值判断是否需要升级

## 4. 数据库字段设计

### 4.1 sys_user 表密码相关字段

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `password_hash` | VARCHAR(512) | NOT NULL | 密码哈希字符串（含算法/版本/Salt/迭代/哈希） |
| `password_algorithm` | VARCHAR(32) | NOT NULL, DEFAULT 'PBKDF2-SHA256' | 当前使用的算法标识，用于快速查找对应 Hasher |
| `password_version` | INT | NOT NULL, DEFAULT 1 | 算法版本号 |
| `password_changed_at` | DATETIME(6) | NULL | 密码最后修改时间 |
| `must_modify_pwd` | TINYINT(1) | NOT NULL, DEFAULT 0 | 首次登录/强制修改标记 |

### 4.2 多版本共存

数据库中可同时存在不同算法的用户记录：

| 用户 | password_algorithm | password_version | 说明 |
|------|-------------------|------------------|------|
| 用户 A | PBKDF2-SHA256 | 1 | 当前默认算法 |
| 用户 B | PBKDF2-SM3 | 1 | 商密合规算法 |
| 用户 C | LEGACY-SM3 | 0 | 旧算法，登录时自动升级 |

## 5. 密码哈希升级策略

### 5.1 升级触发条件

登录验证成功后，检查以下条件，任一满足则触发升级：

1. 存储的 `algorithm` 与当前默认算法不同
2. 存储的 `version` 低于当前默认版本
3. 存储的 `iterations` 低于当前默认迭代次数
4. 哈希字符串格式无法解析

### 5.2 升级流程

```
用户登录
    ↓
使用存储的算法验证密码（旧 Hasher）
    ↓
验证成功
    ↓
检查是否需要升级（NeedsUpgrade）
    ↓ 是
使用当前默认 Hasher 重新哈希明文密码
    ↓
更新 password_hash / password_algorithm / password_version / password_changed_at
    ↓
保存到数据库
```

### 5.3 升级原则

- **透明升级**：用户无感知，登录成功后自动完成
- **安全验证**：必须先通过旧算法验证，才能用新算法重新哈希
- **不回退**：升级后旧格式不再保留

## 6. 登录安全策略

### 6.1 登录失败控制

| 策略 | 参数 | 说明 |
|------|------|------|
| 最大失败次数 | 5 次 | 超过后锁定账号 |
| 锁定时长 | 30 分钟 | 锁定期间拒绝登录 |
| 失败计数重置 | 登录成功时 | 成功后清零失败计数 |

### 6.2 安全事件上报

| 事件类型 | 触发条件 |
|----------|----------|
| `ADMIN_LOGIN_FAILED` | 每次密码错误 |
| `ADMIN_ACCOUNT_LOCKED` | 失败次数达到阈值，账号被锁定 |
| `ADMIN_LOGIN_SUCCESS` | 登录成功 |

### 6.3 首次登录强制修改密码

- 新建用户时设置 `must_modify_pwd = true`
- 登录响应中返回 `MustModifyPassword` 字段
- 前端根据该字段强制跳转修改密码页面

public interface IPasswordHasher
{
    string Algorithm { get; }
    int Version { get; }
    string HashPassword(string password);

public interface IPasswordHasherFactory

## 8. 等保/商密合规对照

| 合规要求 | 本规范对应措施 |
|----------|----------------|
| 密码存储不使用明文/可逆加密 | 使用 PBKDF2 单向哈希，不可逆 |
| 每用户独立 Salt | 16 字节随机 Salt，每用户每次生成 |
| 抗离线暴力破解 | 600,000 次迭代（PBKDF2-SHA256） |
| 算法可替换/升级 | IPasswordHasher 抽象 + 数据库记录算法标识 |
| 登录失败控制 | 5 次失败锁定 30 分钟 |
| 密码修改强制策略 | must_modify_pwd 字段 |
| 审计证据 | 登录成功/失败/锁定均上报安全事件 |
| 算法/版本可审计 | password_algorithm + password_version 字段持久化 |
| 密评证据保留 | 哈希格式自描述，包含算法/版本/参数 |

## 9. 后续扩展方向

以下能力在当前架构下可平滑扩展，不在本次实现范围内：

1. **密码复杂度策略**：长度、复杂度、历史密码检查
2. **密码过期机制**：基于 `password_changed_at` 判断是否过期
3. **历史密码记录**：防止重复使用最近 N 个密码
4. **MFA（多因素认证）**：登录链路已预留扩展点
5. **Token 撤销增强**：当前基于缓存，可扩展为数据库持久化
6. **敏感操作二次授权**：基于 scope 机制扩展更高权限控制
7. **PBKDF2-SM3 启用**：当密评明确要求时，注册为默认 Hasher
